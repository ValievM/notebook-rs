# Архитектура

Принцип: **границы через трейты** (порты), конкретные реализации (адаптеры) за ними, склейка в одном месте. В Rust нет наследования, поэтому ООП-паттерны здесь строятся на трейтах и композиции, а не на классах. Не всё из SOLID нужно: подход «сначала маленький трейт, потом реализация» даёт то же самое (подмена, тесты с фейками) без лишних слоёв.

```
main.rs (CLI)  ──►  service::Notebooks (фасад)
                       │
   ┌───────────────────┼───────────────────────────┐
   ▼                   ▼                           ▼
chunk::Chunker     embed::Embedder          retrieve::Retriever ──► answer (промпт + проверка цитат)
(стратегия)        (порт+адаптеры)          Bm25 / Vector / Hybrid        │
                                                  │                       ▼
                                                  ▼                  llm::Llm
                                             store::Store            (порт+адаптеры)
                                             (репозиторий, SQLite)
```

## Модули
| Модуль | Роль |
|---|---|
| `domain` | Слова предметной области: `NotebookId`, `PassageId` (newtype), `Passage`. |
| `error` | Единый `Error` (thiserror). `anyhow` только в `main.rs`. |
| `chunk` | Трейт `Chunker`, `ParagraphChunker`. Режет источник на фрагменты. |
| `embed` | Трейт `Embedder`, `HashingEmbedder` (офлайн), `cosine`. Вектор помечен именем модели. |
| `store` | Репозиторий над SQLite: FTS5 (BM25) и векторы (BLOB). Единственное место с SQL, миграции через `user_version`. |
| `retrieve` | Трейт `Retriever`; `Bm25Retriever`, `VectorRetriever`, `HybridRetriever` + `reciprocal_rank_fusion`. |
| `answer` | Промпт с пронумерованными фрагментами, разбор JSON, проверка цитат подстрокой. |
| `llm` | Трейт `Llm`; адаптер `CodexExec`. |
| `service` | Фасад `Notebooks`: `add_source`, `ask`; `standard()` собирает обычную связку. |

## Паттерны (и где они)
- **Порт и адаптер (hexagonal)**: `Llm`, `Embedder`, `Store` (репозиторий). Ядро не знает, что за ним `codex` или SQLite.
- **Стратегия**: `Chunker`; позже Markdown/по токенам рядом с абзацным.
- **Компоновщик (composite)**: `HybridRetriever` сам `Retriever` и состоит из `Retriever`-ов.
- **Фасад**: `Notebooks`.
- **Newtype**: идентификаторы нельзя перепутать.
- **Репозиторий**: `Store` прячет SQL; потокобезопасен (`Mutex<Connection>`) для будущего окна.
- Запланировано: **декоратор** (`RetryingLlm`, `CachingEmbedder` вокруг любой реализации), **строитель** для `Notebooks`, когда появится больше настроек.

## Правила
- Новая возможность = новый трейт или новая реализация существующего, а не `if` в чужом коде.
- Тесты используют фейки через трейты (`Recording`, `Fixed`); сети и настоящей модели в тестах нет.
- Вектор сравнивается только с векторами той же модели (`embedding_model` в таблице): смена модели не ломает поиск, старые вектора просто не используются, пока источник не загружен заново.

## Границы масштаба
Поиск векторов перебором по одному блокноту: мгновенно до десятков тысяч фрагментов. Если упрёмся, ADR в `DECISIONS.md` (D-04) называет следующий шаг.
