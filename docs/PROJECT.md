# Проект notebook-rs

## Одной фразой
Свой NotebookLM на Rust: загружаешь источники (заметки, документы, потом PDF и сайты), задаёшь вопросы, получаешь ответ сильной модели со ссылками на места в источниках. Каждая цитата проверена по тексту источника; выдуманная отбрасывается и это видно.

## Зачем
- У существующих аналогов (Open Notebook и др.) модель слабая или настраивается неудобно, а цитаты не проверяются.
- Хочется сильную модель (Codex по подписке ChatGPT), свои надстройки и один лёгкий бинарник на Rust без Docker и баз данных.

## Что выделяет проект
1. **Проверенные цитаты**: цитата должна дословно (с точностью до пробелов и регистра) быть в названном фрагменте.
2. **Модель сменная**: всё за трейтом `Llm`. Сейчас `codex exec`, дальше официальный вход «Sign in with ChatGPT» или любой OpenAI-совместимый адрес.
3. **Всё локально**: одна SQLite-база, эмбеддинги на своей машине.
4. **Свои надстройки** (см. ROADMAP): конспект, сравнение источников, план по материалам, карточки для повторения.

## Где мы сейчас
Работает консольная версия `nb`: `add` (текст, Markdown, PDF, веб-страница; нарезка по заголовкам, индекс BM25 и векторами) и `ask` (гибридный поиск, Codex отвечает JSON-ом, цитаты проверяются; `ask --deep` для вопросов из нескольких частей). 78 тестов. Подробный статус: `ROADMAP.md`.

## Как продолжить в новой сессии
1. Прочитай `AGENTS.md`, затем `ROADMAP.md` (раздел «Следующий шаг»).
2. `cargo test` должен быть зелёным до начала работы.
3. Для живой проверки нужен `codex login status` = «Logged in». База по умолчанию: `~/.notebook-rs/notebooks.db`.

## Откуда взяты идеи
Open Notebook (MIT), прочитан код: схема нарезки (400 токенов, перекрытие 15%), «стратегия → поиски → частичные ответы → синтез». Код оттуда не копируется. Что сравнивали и почему выбрали так: `DECISIONS.md`.

## Файлы и места
- Код: `src/` (карта в `ARCHITECTURE.md`).
- Образец для сравнения лежит отдельно: `~/Dev/Tools/open-notebook-ref/repo` (клон Open Notebook, запущен в Docker; остановка: `docker compose down` в той папке).
